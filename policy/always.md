# 三条核心工程横切规则

无论你在编写前端、后端、接口还是工具脚本，以下三条底线规则始终成立。

---

## 1. 先搜再写，严禁在仓库内重复造轮子

编写任何有具体功能代码之前，按序排查：

1. **当前仓库里是否已经有了**：
   - 必须先在代码库内搜索关键词（例如 `git grep "关键词"` 或全局搜索）；
   - AI 最常见的失误不是引错第三方包，而是在**仓库中已有成熟实现的情况下又写了一套同义实现**。
2. **标准库 / 运行时是否已提供**。
3. **已安装的依赖包中是否已提供**。
4. **最后才考虑引入新依赖**（必须有充分理由，禁止为几行简单逻辑拉入庞大依赖）。

### 绝对禁止手搓的基础设施
以下领域边界情况复杂，**一律使用成熟库，严禁自研/手搓**：
- 密码哈希、加密、签名与 Token 校验；
- 随机数与安全熵；
- 时区与日期时间计算；
- HTTP/JSON/CSV/URL 协议编解码；
- 高精度金额计算与舍入；
- 指数退避重试与限流算法；
- 数据库连接池与 Migration 迁移工具。

> **判据**：“这个组件的所有边界与安全漏洞，我能 100% 穷举并防住吗？” 不能，就用成熟方案。抄入或引入的代码必须完成命名与项目错误模型适配。

---

## 2. 先写测试，并且亲眼见证它红（Fail-to-Pass）

任何缺陷修复（Bugfix）或新功能切片，必须遵循真实 TDD 反馈环：

```text
编写失败测试用例
  ↓
运行验证（必须失败，且失败原因精准对应预期问题）
  ↓
最小实现
  ↓
运行验证（变绿通过）
  ↓
make check 确保无既有功能回退
```

**不能跳过“看它变红”这一步**。
没见过失败的测试，大概率断言了错误的目标（或属于无断言的 Mock 自证）。写完实现再去补测试，往往只会写出“刚好能跑通现有实现”的假测试。

---

## 3. 按可逆性决定投入，不为假想的故障过度设计

- **不可逆的（破坏性数据迁移、对外破坏性 API、第三方付费调用、私钥凭据）**：前置防住，必须有清晰的回滚方案与人类确认；
- **可逆的、局部的实现逻辑**：允许失败，但保证失败透明可见（通过即时测试与 Linter 拦截），快速迭代；
- **不为未发生过的假想故障编写防御代码**；
- **不增加无人使用的配置项与抽象层**。

---

## 4. 零外部网络与真实测试隔离铁律 (Zero External Network in Tests)

在真实业务开发中，测试必须在**完全离线 / 断网**的沙盒中可重复执行：
1. **禁止在测试中发起公网请求**：严禁在单元测试和集成测试中调用真实的第三方 API（如公网 LLM、GitHub API、Stripe、外部 Webhook 等）；
2. **Fake 优于 Mock**：优先编写简单的内存 Fake（如基于内存字典的 FakeStorage、FakeEmailService），杜绝深度侵入实现的 Mock 错觉；
3. **禁止非确定性等待**：严禁在测试中写 `time.sleep(5)` 等待异步，必须使用明确的轮询条件或同步测试调度器；
4. **轻量与自包含**：本地数据库优先使用 SQLite（或本地内存实例），保证新成员 `git clone` 后无需配置外部数据库即可 `make test`。

---

## 5. 无人值守熔断器与原子切片提交 (Circuit Breaker & Atomic Slice)

在夜间无人值守（Loop / Goal 模式）运行时，必须遵守以下安全纪律：
1. **切片级原子提交**：每个切片通过 `make check` 后，必须立即进行一次语义清晰的原子 Git Commit (`git commit -m "feat(slice-N): ..."` )；
2. **自愈重试熔断器 (Circuit Breaker)**：
   - 同一切片内运行 `make check` 失败，Agent 自主修复上限为 **3 轮**；
   - 若 3 轮后依然报错，**立即停止盲目修改**，执行 `git checkout -- .` 回滚本轮破坏性改动；
   - 在 `docs/walkthrough.md` 中标记该切片为 `BLOCKED`，详细记录错误堆栈与阻碍原因，安全退出循环；
   - 绝不因单个切片卡死而破坏整晚已稳定提交的其他切片代码。
