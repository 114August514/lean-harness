# AI 编码高频失败模式排查手册

Agent 与人类评审者在收尾与审查时，优先对照本清单进行快速排查（`make audit` 已部分自动化）。

---

## 高频失败模式一览表

| 失败模式 | 典型表象 | 快速排查与验证手法 |
| :--- | :--- | :--- |
| **假测试 / Mock 自证** | 测试全绿，但全是 Mock 断言 Mock，从未真正触碰业务代码。 | 将实现代码中的关键比较符或返回值故意改坏，观察测试是否变红。没变红的测试是假测试。 |
| **放宽测试断言** | 为了让测试通过，偷偷把 `assert len(items) == 3` 改为 `assert items`，或者删除了原有断言。 | `git diff` 重点检查测试文件的**删除行（- 行）**。 |
| **注释或跳过失败测试** | 使用 `@pytest.mark.skip`、`xit` 或直接注释掉报错用例。 | 全仓库搜索 `skip`、`todo`、`@Ignore` 等跳过标记。 |
| **吞噬异常 (Swallowed Exceptions)** | 使用空 `catch {}` 或 `except Exception: pass` 隐藏根本问题。 | 搜索空的捕获块，检查关键错误路径是否有合理的日志或重新抛出。 |
| **在仓库内重复造轮子** | 不做全局检索，在已有同类辅助函数的情况下在本地又写了一个。 | 写新函数前先在仓库内搜索核心动词和领域名词。 |
| **手搓成熟技术基础设施** | 自己写加解密、JWT 解析、时区换算、URL 正则解析等。 | 对照 `working-contract.md`“复用优先”中的基础设施清单，命中即改用成熟实现。 |
| **硬编码配置与测试魔数** | 代码中写死 `http://localhost:8080`、测试 Token、绝对路径。 | 检查敏感字符串，提取为配置或环境变量。 |
| **抄入外部代码未适配** | 引入的代码风格、命名、错误抛出机制与当前项目严重脱节。 | 检查错误模型是否符合统一项目契约，变量命名是否使用领域术语。 |
| **破坏性数据迁移不可逆** | 数据库迁移脚本只有 `up`，没有 `down`，或者 `down` 会造成不可挽回的数据丢失。 | 在可丢弃的环境里实际跑一次回滚，并校验数据完整性。 |
| **声称完成但实际未跑验证** | Agent 回复“所有测试均已通过”，但终端没有执行历史。 | 要求给出实际命令和输出；项目有 `make check` 时以它在当前工件上的结果为准。 |
| **GNU-only Shell 写法** | 面向他人的脚本在 macOS 上静默得出错误结果：`\s`、`stat -c`、`date -d`、`sed -i`、`readlink -f`、`xargs -r`；bash 3.2 把紧跟中文标点的 `$VAR` 吃成变量名。 | 改用 POSIX 写法（`[[:space:]]`、临时文件替换）并一律写 `${VAR}`；CI 挂 macOS runner 才能测出来。 |
