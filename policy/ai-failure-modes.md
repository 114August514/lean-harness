# AI 编码高频失败模式排查手册

Agent 与人类评审者在收尾与审查时，优先对照本清单进行快速排查（`make audit` 已部分自动化）。

---

## 高频失败模式一览表

| 失败模式 | 典型表象 | 快速排查与验证手法 |
| :--- | :--- | :--- |
| **假测试 / Mock 自证** | 测试全绿，但全是 Mock 断言 Mock，从未真正触碰业务代码。 | 将实现代码中的关键比较符或返回值故意改坏，观察测试是否变红。没变红的测试是假测试。 |
| **放宽测试断言** | 为了让测试通过，偷偷把 `assert len(items) == 3` 改为 `assert items`，或者删除了原有断言。 | `git diff` 重点检查测试文件的**删除行（- 行）**。 |
| **注释或跳过失败测试** | 使用 `@pytest.mark.skip`、`xit` 或直接注释掉报错用例。 | 全仓库搜索 `skip`、`todo`、`@Ignore` 等跳过标记。 |
| **吞噬异常 (Swallowed Exceptions)** | 使用空 `catch {}` 或 `except Exception: pass` 隐藏根本问题。 | 搜索空的捕获块，检查关键错误路径是否有合理的日志或重新抛出。 |
| **在仓库内重复造轮子** | 不做全局检索，在已有同类辅助函数的情况下在本地又写了一个。 | 在编写具体函数前，强制 `git grep` 核心动词。 |
| **手搓成熟技术基础设施** | 自己写加解密、JWT 解析、时区换算、URL 正则解析等。 | 对照 `always.md` 禁区，命中即阻断。 |
| **硬编码配置与测试魔数** | 代码中写死 `http://localhost:8080`、测试 Token、绝对路径。 | 检查敏感字符串，强制提取为环境变量或配置文件。 |
| **抄入外部代码未适配** | 引入的代码风格、命名、错误抛出机制与当前项目严重脱节。 | 检查错误模型是否符合统一项目契约，变量命名是否使用领域术语。 |
| **破坏性数据迁移不可逆** | 数据库迁移脚本只有 `up`，没有 `down`，或者 `down` 会造成不可挽回的数据丢失。 | 必须实地在沙箱运行一次 `migrate down` 并校验数据完整性。 |
| **声称完成但实际未跑验证** | Agent 回复“所有测试均已通过”，但终端没有执行历史。 | 必须由 Harness 或开发者亲手执行一次 `make check`。 |
