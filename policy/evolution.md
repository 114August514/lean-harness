# 规则演进协议

本协议约束 Lean Harness 自身（`policy/`、`skills/`、工具与模板）如何吸收经验：经验优先落到机器能检查的资产里，自然语言规则只收录无法机械检查的部分，并定期删减。

## 三层沉淀

| 层 | 载体 | 何时沉淀 |
| --- | --- | --- |
| 1. 可执行资产 | 项目测试、类型检查、lint 规则、种子数据 | 能用断言、类型或 lint 锁定的经验，直接写成这些资产；是否值得长期保留按 `working-contract.md` 的“测试与验证”判断 |
| 2. 失败模式清单 | `ai-failure-modes.md` | 同一类系统性失误在不同任务中出现至少两次 |
| 3. 工具与模板 | `bin/`、`templates/`、`Makefile` | 实际使用中发现更好的检查、诊断或默认配置，经人类审查后合入，让之后的项目直接受益 |

## 规则

1. **运行时不改主规则。** Agent 不在任务中途自行改写 `policy/`、`skills/` 或系统提示；当次的反思只留在当次上下文。需要改规则时，作为独立变更提出并经人类审查。
2. **出现两次再写（2-strike）。** 单次笔误直接修，不新增规则。同一类系统性失误出现两次（例如两次在测试里访问公网、两次写出无断言的 mock 测试），才向 `ai-failure-modes.md` 追加一条：一行写表现，一行写纠正动作。
3. **能检查的不写成提示。** 能用测试、类型或 lint 锁定的边界，不写成要模型记住的文字；文字只留给架构意图和无法机械检查的反模式。
4. **定期删减。** 基础模型大版本升级或清单变长时复查 `ai-failure-modes.md`：已成常识或已被工具拦截的条目直接删除。
5. **规则变更单独提交。** policy 与 skills 的修改不和功能改动混在同一个 commit，便于审查和回退。
