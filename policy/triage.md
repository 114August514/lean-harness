# 双轨制任务分流策略 (Two-Speed Triage)

拒绝所有任务千篇一律地走重度多阶段审批。按**可逆性与影响半径**将任务明确分流为双轨，保持高流速的同时守住致命红线。

---

## 任务分流对照表

| 分类 | 典型场景 | 执行路径 | 人类审查介入点 |
| :--- | :--- | :--- | :--- |
| **快轨 (Fast Loop)**<br>日常高频 (80%) | • 缺陷修复 (Bugfix)<br>• 既有骨架内的功能新增<br>• 代码重构与测试补充<br>• 文档、注释、类型修复 | **全自动自愈环**：<br>1. 编写失败测试 (先红)<br>2. 最小实现代码 (后绿)<br>3. `make check` 自动拦截<br>4. 自动生成 Git Commit | **仅在最终看 Git Diff**。<br>中间过程零卡点，机器通过即可交付。 |
| **慢轨 (Deliberate Loop)**<br>结构与高危 (20%) | • 数据库 Schema / 迁移脚本<br>• 对外 API 破坏性变更<br>• 权限、认证与计费模型<br>• 从 0 搭建新系统/新模块 | **意图锚点对齐 (Spec Kit 风格)**：<br>1. 产出 1 页以内的轻量 Spec (目标、非目标、可判定验收标准)<br>2. 明确仓外副作用与回滚方案<br>3. 人类确认一次后放行执行 | **前置确认一次 Spec 契约**；<br>完成后复核 Schema Diff 与迁移回滚测试。 |

---

## 判定规则与禁区

1. **Bug 修复严禁当作微改（T0）滑过去**：
   哪怕只改动一个字符，只要它是 Bug，就证明当前测试集存在覆盖盲区。必须先新增会变红的回归测试。
2. **碰触以下目录或内容，强制升格为慢轨**：
   - 数据库迁移（如 `migrations/`、DDL 变更）；
   - 公共对外接口契约（如 `contracts/`、OpenAPI 定义）；
   - 权限校验逻辑与敏感密钥处理；
   - 生产部署与环境变更。
3. **慢轨中的意图 Spec 必须包含 Non-goals（非目标）**：
   清楚地写明“这次坚决不做什么”，是防止 Agent 自作主张扩大改动范围的最有效护栏。
