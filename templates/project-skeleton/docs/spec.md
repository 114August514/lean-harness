- [ ] ❌ [其他本次坚决不做的事]

## 4. 第一颗“曳光弹”定义 (The Tracer Bullet)
在实现所有业务逻辑之前，必须先打通一条贯穿“界面 $\rightarrow$ API $\rightarrow$ 存储”的最薄可运行链路：
- **曳光弹行为**：敲下 `make dev`，打开页面能点一个按钮，返回一条固定的 Hello 数据。
- **排雷目标**：在第 10 分钟证明构建、依赖、端口、网络和基本渲染链路 100% 畅通。

---

## 5. 验收标准与 Demo 演示剧本 (Demo Script)
按机器可判定标准编写，打上稳定 REQ-ID，并附带最终交付时的 30 秒演示剧本：
- [ ] `REQ-001`: [正常输入时，系统必须返回 200 并展现新增项]
- [ ] `REQ-002`: [非法输入时，系统必须返回明确报错信息，不产生脏数据]

### 30 秒 Demo 体验剧本：
1. 运行 `make demo`；
2. 打开 `http://localhost:3000`（或运行 CLI 演示）；
3. 观察预置种子数据与交互反馈；
4. 验证是否符合主旅程预期。

---

## 6. 垂直切片清单与进展 (Vertical Slices & Progress)

> **切片约定**：
> 1. 一次推进一个切片，每片交付可观察的端到端结果；
> 2. 切片完成后 `make check` 通过，再勾选 `[x]` 并提交（如 `git commit -m "feat(slice-N): ..."`）；
> 3. 修复缺陷时，新增的回归测试先确认在修复前失败；
> 4. 阶段结束或无人值守运行结束前，把进展写进 `docs/walkthrough.md`。

- [ ] **Slice 0 (Tracer Bullet)**: 初始极简骨架连通，`make check` 绿，`make demo` 打印基础响应。
- [ ] **Slice 1**: 核心数据持久化与存储（支持种子数据加载 `make seed`）。
- [ ] **Slice 2**: 核心业务规则与主旅程 API 接口（附行为测试）。
- [ ] **Slice 3**: 异常边界处理、输入校验与日志/错误提示。
- [ ] **Slice 4**: 用户端交互/CLI/前端页面与最终 30 秒 Demo 交付。
