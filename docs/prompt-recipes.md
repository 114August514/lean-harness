# Lean Harness 黄金驱动 Prompt 体系 (Prompt Recipes)

本手册汇总了基于学术前沿（Reflexion、SED 漂移研究、DSPy）与工业标杆（Claude Code、Cursor Rules）实践经验提炼出的 **AI Agent 黄金驱动 Prompt 体系**。

这些 Prompt 专为克服大模型的两大天然致命缺陷而设计：
1. **产出强迫症 (Action Bias)**：防止模型不看上下文便“想当然”与“重复造轮子”；
2. **长程注意力稀释 (Dilution Effect)**：防止模型在长时间编码中偏离顶层架构约束。

---

## 一、 阶段 1：立项与需求塑形 (Shaping Prompt)

> **使用时机**：当人类脑海中只有一个模糊的产品想法（如“做一个服务监控小工具”），希望 Agent 花 3 分钟替你把边界定死、把切片拆清，而不是一上来就胡乱写出几百行半成品代码。

```markdown
【项目意向】：我想开发 [在此处简述你的想法，例如：一个轻量级的服务可用性监控与报警服务 Uptime Sentinel]。

【执行角色与规范】：
请作为资深架构师，严格遵循 Lean Harness 工程规范。
⚠️ 坚决禁止直接开始编写业务实现代码！你的首要任务是完成需求塑形 (Shaping)。

请在 `docs/spec.md` 中填写并交付以下内容：
1. 唯一主旅程 (Primary Journey)：描述用户从输入、系统处理到最终呈现的确定性闭环；
2. ★ 3 条明确非目标 (Non-goals)：强制列出本次绝对不碰的范围（如：不做多用户鉴权、不做复杂图表看板、不对接真实外部收费网关）；
3. 核心概念实体：用最简 TS/Python 类型定义 1 个核心数据实体；
4. 首颗曳光弹 (Tracer Bullet)：定义终端上最先打印出的最小连通输出，以及 30 秒 Demo 体验剧本；
5. 垂直切片清单 (Slice Backlog)：在第 6 节按依赖顺序拆解出 3~4 个独立切片 (Slice 0~3)，每个切片必须具备明确的验收测试命令。

完成 `docs/spec.md` 塑形后立即停止，等待我确认后再进入下一阶段。
```

## 二、 阶段 2：先调研后干活（防想当然·实战驱动 Prompt）

> **使用时机**：进入具体切片开发或新增关键特性时，彻底阻断模型直接手搓代码的冲动。

```markdown
【切片目标】：开始实现 [Slice N：具体功能，例如：SQLite 持久化与种子加载]。

【执行硬性铁律 —— 先调研后干活 (No Code Before Evidence)】：
⚠️ 严禁直接输出实现代码！在写任何业务代码之前，必须先完成“三维侦察”：
1. 库内查重：使用搜索工具检索代码库，确认是否已有相似实现或可用实体；
2. 生态查重：严格排查语言标准库与已有依赖，坚决禁止自研手搓成熟能力（如网络请求、时区、正则解析、加解密等）；
3. 真实契约确证：调用的任何模块或外部库，必须确证其真实 API 签名，禁止凭记忆“想当然”猜测入参。

【交付要求】：
在动手修改代码前，你必须在回答中首先输出【三维侦察简报】：
- 库内可复用资产：...
- 本次选用的成熟标准库/依赖：...
- 确证的真实 API 接口与依据：...

证据确凿后，方可进入先红后绿 TDD 测试与最小代码实现！
```

## 三、 阶段 3：通宵挂机与切片自愈 (Overnight Autonomous Prompt)

> **使用时机**：需求塑形确认后，人类准备去睡觉（如触发 OMP `--plan-yolo`、Claude Code `/goal` 或自动化循环），要求模型连跑几小时，既推进功能，又绝不死循环毁坏代码。

```markdown
【任务目标】：按照 `docs/spec.md` 中的垂直切片清单，自主推进系统实现。

【执行守则与硬性护栏】：
1. 严格单切片递进：一次只领跑一个切片（存储 → 核心逻辑 → 接口），严禁跨切片大面积铺开；
2. 遵循三维侦察：每开一个新切片，先查标库与既有代码，严禁重复造轮子；
3. 先红后绿 (Fail-to-Pass)：每个切片必须先写伴生失败测试，确认变红，再写最小实现使其变绿；
4. 零外部网络原则：测试用例严禁调用公网外部 API，全部使用本地 SQLite 与内存 Fake；
5. 切片级原子提交 (Atomic Commit)：切片通过 `make check` 变绿后，立即在 `docs/spec.md` 勾选 [x]，并执行切片原子提交（git commit -m "feat(slice-N): ..."）；
6. 自愈熔断器 (Circuit Breaker)：若 `make check` 报错，自主诊断修复上限为 3 轮；若 3 轮未收敛，必须执行 `git checkout -- .` 回滚本轮破坏性尝试，在晨报中标记为 BLOCKED 并安全退出；
7. 晨报交付物：任务结束前更新 `docs/walkthrough.md`，提供包含完成切片、当前状态及 `make demo` 30 秒交互指南的晨报。
```

## 四、 阶段 4：晨醒 1 分钟验货 (Morning Verification Prompt)

> **使用时机**：人类醒来后，快速要求 Agent 提供交付综述，或辅助人类快速完成验收。

```markdown
请根据昨晚的交付产物，为我呈现验收摘要：
1. 昨晚成功推进并原子提交了哪些切片？
2. 当前代码库 `make check` 是否全绿？
3. 请给出执行 `make demo` 的具体指令与 30 秒玩转步骤；
4. 是否触发了自愈熔断或存在需要人类决策的事项？
```
